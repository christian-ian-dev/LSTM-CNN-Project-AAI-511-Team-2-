Music Composer Classification

Using LSTM and CNN Deep Learning Algorithms

Lashana Narayan, Idrees Khan, Christian Lopez

August 2026

Abstract 

  The automatic classification of musical composers is a challenging task within music information retrieval that requires modeling complex temporal, harmonic, and structural characteristics. This study evaluates and compares the effectiveness of deep learning architectures: Long Short-Term Memory (LSTM) networks and Convolutional Neural Networks (CNNs); in identifying four classical composers (Bach, Beethoven, Chopin, and Mozart) from symbolic MIDI data. Utilizing a rigorously cleaned and balanced dataset of 360 MIDI files, the methodology contrasts two distinct feature representation strategies: sequential pitch and chord tokens for the LSTM, and two-dimensional piano roll images for the CNN. Performance evaluations reveal that the sequence-based LSTM model achieved a higher accuracy that was significantly outperforming the spatial-based CNN model. This disparity underscores that LSTMs effectively capture the essential ordered and temporal dependencies of musical compositions, whereas CNNs struggle due to the loss of sequential context when treating music as static images. While both models exhibited the most confusion distinguishing between composers with shared Classical-era stylistic overlap (Mozart and Beethoven), the findings conclusively demonstrate that sequence-based models are better suited for symbolic music classification tasks.

Keywords: Music Composer Classification, Deep Learning, Long Short-Term Memory (LSTM), Convolutional Neural Network (CNN), Music Information Retrieval (MIR), Symbolic Music Analysis, MIDI

Music Composer Classification Using LSTM and CNN Deep Learning Algorithms

The automatic classification of musical composers represents a challenging problem at the intersection of machine learning, music information retrieval, and pattern recognition. Musical compositions contain complex temporal, harmonic, and structural characteristics that distinguish one composer from another, making them well suited for analysis using deep learning techniques (Yang et al., 2021). Recent advances in neural networks have enabled models to learn sophisticated representations directly from symbolic music data such as sheet music and MIDI representations (Deepaisarn et al., 2023; Le et al., 2025; Yang et al., 2021). Composer classification has applications in music recommendation, music generation, and musicological analysis of historical compositions (Yang et al., 2021).

The objective of this project is to develop and evaluate deep learning models capable of accurately identifying the composer of a musical piece. Using a dataset of musical compositions represented through MIDI and related feature extraction techniques, multiple neural network architectures were explored and compared. The study investigates the effectiveness of these approaches in capturing stylistic patterns that differentiate composers and evaluates model performance using standard classification metrics. The results contribute to the growing body of research applying deep learning techniques to symbolic music analysis and composer identification (Deepaisarn et al., 2023; Le et al., 2025; Yang et al., 2021).

Dataset Description

The dataset for this project originates from the Kaggle "MIDI Classic Music" corpus, containing MIDI files from various classical composers. MIDI data provide a structured representation of musical elements, including pitch, duration, timing, and instrumentation, making them well suited for machine learning applications. The data was filtered to retain compositions from four target composers: Bach, Beethoven, Chopin, and Mozart. A quality control pipeline was implemented using the pretty_midi library to validate each file, removing corrupted, truncated, or empty files that contained no instruments or musical notes. Tools such as pretty_midi facilitate the extraction and analysis of these features, enabling the transformation of musical compositions into formats suitable for neural network training (Raffel & Ellis, 2014).

Methodology

Data Preprocessing

To address class imbalance, random undersampling was applied to match the size of the smallest composer class, ensuring equal representation across all four categories. The balanced dataset was then split into training (80%) and test (20%) sets (288 train files and 72 test files) using stratified sampling at the file level, preventing data leakage by ensuring that segments from the same composition do not appear in both sets. This same train/test split was used for both models to enable fair comparison.

Exploratory Data Analysis

        In this study, we present an in-depth Exploratory Data  Analysis (EDA) of a curated collection of classical MIDI files. As an increasingly crucial format in  Music Information Retrieval (MIR), MIDI  provides a versatile symbolic representation of music that allows for robust computational analysis of stylistic traits (Bhandari et al., 2024). The objective of this analysis was to identify structural and stylistic differences across four master composers: Johann Sebastain Bach, Ludwig van Beethoven, Frederic Chopin, and Wolfgang Amadues Mozart. By extracting and analyzing symbolic features, we aimed to lay the groundwork for downstream classification modeling.

Raw symbolic music datasets sourced from the internet often suffer from metadata inaccuracies, corruption, and structural inconsistencies (Xu et al., 2024). Therefore, our first priority was to establish a rigorous data cleaning pipeline.

Initially, we compiled a dataset of 1,630 potential MIDI files attributed to our four target composers. During the validation phase, we implemented automated checks to identify and remove structurally compromised files. This process successfully isolated and removed four corrupt/empty files.

Following the removal of corrupted data, we were left with 1,626 valid files. However, the initial distribution revealed a significant class imbalance.

  • Chopin: 136 files
  • Beethoven: 132 files
  • Bach: 122 files
  • Mozart: 90 files

In standard MIR machine learning tasks, failing to address class imbalance can bias models toward majority classes, skewing classification accuracy and generative evaluation (Shin & Kaneko, 2025). To ensure a fair representation across all composers, the dataset was undersampled to match Mozart’s count. As a result, the final balanced dataset consisted of exactly 360 files, or 90 files per composer.

To convert the raw MIDI events into analyzable tabular data, we engineered a feature extraction script which was developed using the pretty_midi library. Cross-modal retrieval and classification tasks rely heavily  on extracting discrete features from unaligned modalities such as audio and symbolic music (Wu et al., 2025).

The following key metrics were extracted for each piece:

  • Length_Seconds: Total duration of the composition
  • Total_notes: The absolute count of the note events
  • Notes_Per_Second: A proxy for rhythmic density
  • Estimated_BPM: The inferred tempo
  • Average_Pitch & Pitch_Range: Indicators of harmonic and melodic boundaries

During the batch extraction process, our logs generated recurring RuntimeWarning messages:

  • Tempo, Key, or Time signature change events found on non-zero track
  • This is not a valid type 0 or type 1 MIDI file

We concluded that this is a common artifact when dealing with crowdsourced MIDI data, indicating that the metadata events are misplaced. Consequently, the Estimated_BPM feature in our dataset may contain noise; as irregular track assignments can interfere with accurate tempo estimations.

To contextualize our extracted features, we generated a comprehensive grid of visualizations. These visual distributions provide clear, quantifiable insights into the distinct compositional styles of the four musicians.

Long Short-Term Memory (LSTM)

LSTM networks are a specialized variant of Recurrent Neural Networks (RNN) designed to model sequential data by maintaining information across long time intervals (Hochreiter & Schmidhuber, 1997). Unlike standard RNNs, which suffer from vanishing gradient problems when learning long-range dependencies (Bengio et al., 1994), LSTMs employ a gating mechanism consisting of input, forget, and output gates that regulate information flow through the network. This architecture enables the model to selectively retain or discard information from previous time steps, making it particularly effective for tasks involving temporal sequences. In the context of music classification, LSTMs are well-suited to capture melodic progressions, harmonic sequences, and rhythmic patterns that unfold over time (Le et al., 2025). The sequential nature of musical compositions—where the ordering of notes carries significant meaning—aligns naturally with the LSTM's strength in modeling ordered dependencies. Prior research in music information retrieval has demonstrated the effectiveness of LSTMs for tasks including music generation, chord recognition, and genre classification (Deepaisarn et al., 2023).

The LSTM model was built and trained to classify the four composers—Bach, Beethoven, Chopin, and Mozart—using note and chord sequences extracted from the balanced dataset of 360 MIDI files.

Feature Representation: Note Sequence Representation

The music21 library was used to parse each MIDI file and convert it into a sequence of tokens. Each note became a pitch string, such as "C4," and each chord became a joined string of its normal-order pitch classes. Across all 360 files, this process produced a vocabulary of 842 unique tokens.

One challenge was the substantial variation in sequence length: the shortest sequence contained only 29 tokens, while the longest contained over 5,200. Feeding sequences of wildly different lengths directly into an LSTM isn't practical, so each piece was split into fixed windows of 100 tokens. Because Mozart's compositions also showed the widest variability in notes-per-second (roughly 4 to 24 notes per second, per the EDA), the windowing approach incorporated two augmentation strategies to help the model generalize across this variation: time-stretching, which generated 0.9x and 1.1x duration-scaled versions of each file, and random cropping, which drew 10 random 100-token windows from each sequence rather than sliding a fixed window sequentially across it. This approach preserved more of each piece's variation while transforming the 360 original files into a substantially larger and more varied set of training examples than a simple sequential-windowing method would have produced. The resulting windows were split 80/20 into training and test sets, with stratification used to preserve the proportional representation of each composer in both sets.

Model Architecture

A standard sequence classification architecture was implemented:

  • An embedding layer to turn the integer-encoded tokens into 64-dimensional vectors
  • Two stacked LSTM layers (128 units, then 64 units), each followed by a dropout layer (0.3) to help control overfitting
  • A dense layer (32 units, ReLU activation)
  • A final softmax output layer for the 4-way composer classification

The model was trained for 30 epochs using the Adam optimizer, categorical cross-entropy loss, and a batch size of 64.

Interpretation

These results are consistent with the patterns observed in the EDA earlier in the project. Chopin's Romantic-era piano writing is stylistically distinct from the other composers in this dataset, which likely explains why it was the easiest composer to classify. Bach's lower and more tightly clustered note density, as shown in the EDA, likely provided the model a clearer classification signal to key on, though its precision of 0.71 suggests the model still over-predicts Bach for some Beethoven and Mozart pieces.

Beethoven and Mozart, on the other hand, both fall within the Classical/early-Romantic tradition and share more overlapping stylistic characteristics — similar chord progressions, comparable rhythmic patterns, and closer historical proximity to each other than to Bach or Chopin. That overlap likely explains why the model confused them with each other, and with Bach, more often than it confused either of them with Chopin.

Limitations and future improvements

Several improvements could be explored in future work:

  • More features: the model currently only sees pitch/chord information. Adding rhythm, note duration, or dynamics (velocity) could give it more to work with, especially for telling Beethoven and Mozart apart.
  • Further tuning: additional epochs, a learning rate schedule, or a wider hyperparameter search across different LSTM sizes, dropout rates, window lengths, or amounts of augmentation could likely push accuracy higher still.
  • Additional augmentation types: pitch transposition, shifting pieces up or down by a few semitones, is another common, low-cost augmentation for symbolic music that wasn't tested here and could further help underrepresented patterns.

Overall, the LSTM's 79.14% test accuracy across four composers substantially exceeded the 25% random-guess baseline. This result indicates that the model learned real, meaningful musical patterns, and that the augmentation strategy produced a meaningful improvement over an initial sequential-windowing approach, particularly for Mozart, the previously weakest-performing class. The model remains clearly better at separating the more stylistically distinctive composers, such as Bach and Chopin, than the more similar pair, such as Beethoven and Mozart, though the gap between the two groups narrowed with augmentation.

Convolutional Neural Network (CNN)

Convolutional Neural Networks are deep learning architectures originally developed for image recognition that excel at detecting spatial patterns through hierarchical feature extraction (LeCun et al., 1998). CNNs apply learnable filters across input data to identify local features, with successive layers capturing increasingly abstract representations. Max pooling operations provide translation invariance, allowing the network to recognize patterns regardless of their exact position. While traditionally applied to visual data, CNNs have proven effective for music classification when audio is represented as two-dimensional time-frequency images such as spectrograms or piano rolls (Yang et al., 2021). In this representation, the horizontal axis encodes time while the vertical axis encodes pitch, transforming music into a visual format where harmonic structures appear as vertical patterns and melodic lines appear as horizontal trajectories. CNNs can thus learn to identify textural characteristics, chord voicings, and polyphonic density—features that distinguish compositional styles. This spatial approach to music analysis complements the sequential approach of LSTMs, as it captures simultaneous note relationships that may be less apparent when music is processed as a linear sequence.

Feature Representation: Piano Roll Representation

For the CNN model, we converted each MIDI file into a piano roll representation—a 2D matrix where the x-axis represents time and the y-axis represents pitch. Each cell contains the velocity (intensity) of a note at a given time step, normalized to the [0, 1] range by dividing by 127 (the maximum MIDI velocity). This representation transforms the sequential music data into an image-like format suitable for convolutional processing.

The piano roll was configured with:

  • Pitch range: 21 (A0) to 108 (C8), covering the standard 88-key piano
  • Time resolution: 10 frames per second
  • Segment duration: 10 seconds (100 frames per training example)

From each MIDI file, we extracted 5 random segments to augment training data while maintaining diversity. Segments with note density below 1% were filtered to remove near-silent passages that lack discriminative features.

Training Procedure

The model was compiled with:

  • Optimizer: Adam with default learning rate (0.001)
  • Loss function: Categorical cross-entropy
  • Batch size: 32

To improve training stability and prevent overfitting, we employed two callbacks:

  1. ReduceLROnPlateau: Reduces learning rate by 50% when validation loss plateaus for 3 consecutive epochs (minimum LR: 1e-6)
  2. EarlyStopping: Terminates training when validation loss fails to improve for 7 epochs, restoring the best weights

Training was capped at 50 epochs, though early stopping typically terminated training earlier.

The CNN model was trained for up to 50 epochs with early stopping monitoring validation loss. Training was terminated early when validation loss failed to improve for 7 consecutive epochs, with the best weights restored automatically.

Interpretation

The CNN's moderate performance suggests that spatial patterns in piano roll representations capture some composer-specific information, but this representation has fundamental limitations for music classification. Several factors contribute to the CNN's underperformance:

Loss of temporal information. CNNs process the piano roll as a static image, applying translation-invariant filters across both time and pitch dimensions. While this approach successfully captures local harmonic structures and note clusters, it struggles to model the sequential dependencies that characterize musical style (Huang et al., 2019). A chord progression that defines a composer's style appears as scattered spatial features rather than a coherent temporal pattern.

Velocity normalization trade-offs. We normalized MIDI velocities to [0, 1] to ensure consistent input scaling. While this prevents the model from overfitting to loudness variations, it may discard stylistically relevant dynamic information. Beethoven's dramatic dynamic contrasts, for instance, become indistinguishable from Mozart's more restrained dynamics (Chew, 2014).

Segment-level classification. Each 10-second segment was classified independently, ignoring the broader musical context. Composer style often emerges over longer time scales through thematic development, formal structure, and motivic transformation—features that short segments cannot capture (Conklin, 2003).

Class similarity. The substantial confusion between Mozart and Beethoven reflects genuine stylistic overlap. Both composers worked within Classical-era conventions, employing similar textures (Alberti bass, scalar passages), phrase structures (4- and 8-bar phrases), and harmonic progressions (Rosen, 1997). The CNN's spatial filters cannot reliably distinguish these composers when their local note patterns are nearly identical.

Limitations and Future Improvements

Several limitations constrain the CNN's performance in this study:

  1. Architecture simplicity. Our two-layer CNN may lack the depth required to learn hierarchical musical features. Deeper architectures with residual connections have shown improved performance on music classification tasks (Won et al., 2020).
  2. Limited hyperparameter tuning. Due to computational constraints, we did not exhaustively search the hyperparameter space. Filter sizes, layer depths, and regularization strengths were selected based on common practices rather than systematic optimization.
  3. Fixed segment length. The 10-second segment duration was chosen heuristically. Shorter segments may capture insufficient context, while longer segments reduce training data volume and increase computational cost.
  4. Piano roll resolution. The 10 fps temporal resolution may be too coarse to capture rapid ornamentations and subtle rhythmic variations that distinguish composers (Yang et al., 2017).
  5. Single-channel input. We used velocity as a single channel. Multi-channel representations incorporating onset detection, sustain, or harmonic features might provide richer information (Dong et al., 2018).

Several directions could improve CNN performance on composer classification:

  1. Architectural enhancements. Implementing deeper networks with residual connections (He et al., 2016), or employing architectures specifically designed for spectrogram-like inputs such as VGGish (Hershey et al., 2017), may improve feature learning. Attention mechanisms could help the model focus on musically salient regions of the piano roll (Huang et al., 2019).
  2. Multi-resolution input. Providing the CNN with piano rolls at multiple temporal resolutions (e.g., 5, 10, and 20 fps) could capture both fine-grained note patterns and broader rhythmic structures simultaneously (Schlüter & Böck, 2014).
  3. Data augmentation. Beyond random segment extraction, augmentations such as pitch shifting, time stretching, and velocity perturbation could increase training data diversity and reduce overfitting (McFee et al., 2015).
  4. Hybrid architectures. Combining CNN feature extraction with recurrent layers (CRNN) could preserve spatial pattern recognition while modeling temporal dependencies (Choi et al., 2017). This approach has shown strong results in music tagging and genre classification tasks.
  5. Ensemble methods. Combining predictions from multiple CNN models trained with different initializations or segment lengths could reduce variance and improve overall accuracy (Pons et al., 2018).

Chopin was the easiest to classify for both models. His Romantic piano style—with rolling arpeggios, rubato, and distinctive left-hand patterns—stands out from the three Classical/Baroque composers (Burkholder et al., 2014). Even the CNN could pick up on these spatial patterns.

Why LSTM Works Better

Our results support what other researchers have found: music is fundamentally sequential, and models that respect this structure perform better (Huang et al., 2019; Deepaisarn et al., 2023). The LSTM's gating mechanism lets it remember important information over long sequences while forgetting irrelevant details (Hochreiter & Schmidhuber, 1997). For composer classification, this means it can track things like "we're in a Bach-style fugue" across many notes, even when individual passages might look similar to other composers. The CNN's translation-invariant filters are great for images where a cat is a cat regardless of where it appears. But in music, when something happens matters. A V-I cadence at the end of a phrase means something different than the same notes in the middle. The CNN can't make this distinction (LeCun et al., 1998). That said, CNNs aren't useless for music. Hybrid approaches that combine CNN feature extraction with recurrent layers (CRNNs) have shown strong results in other music tasks (Choi et al., 2017). Our CNN also performed reasonably well on Bach and Chopin, suggesting it does capture some useful spatial information.

Conclusion

We compared two deep learning approaches for classifying piano compositions by composer: an LSTM trained on note sequences and a CNN trained on piano roll images. Using MIDI files from Bach, Beethoven, Chopin, and Mozart, we found that the LSTM achieved 79% accuracy while the CNN achieved 51% accuracy.

The findings indicate that sequential representations are more effective for this symbolic music classification task. The LSTM’s ability to learn temporal dependencies, including note order and phrase development, proved more effective than the CNN’s spatial pattern recognition approach.

For practical applications in music information retrieval, these results suggest that sequence-based models are well suited for symbolic music classification tasks. Researchers working with MIDI data may benefit from representing music as ordered tokens rather than relying exclusively on two-dimensional image-like representations.

This work also highlights the challenge of distinguishing composers with overlapping stylistic characteristics. Mozart and Beethoven were frequently confused by both models, reflecting their shared Classical-era musical vocabulary. This finding suggests that style classification may be a useful complementary direction for future research.

Limitations

  1. Dataset size. We used only 90 files per composer after balancing. More data would likely improve both models, especially the CNN which showed signs of overfitting. Larger datasets like the MAESTRO corpus could provide more robust results.
  2. Limited composers. Four composers isn't enough to make broad claims about "composer classification" in general. Our findings might not hold for composers with more similar styles (e.g., Haydn vs. Mozart) or more distinct styles (e.g., Debussy vs. Bach).
  3. Piano only. All pieces were solo piano works. Orchestral, chamber, or vocal music would present different challenges and might favor different model architectures.
  4. MIDI limitations. MIDI captures pitch and timing but loses expressive nuances like articulation, pedaling, and subtle tempo variations (Raffel & Ellis, 2014). These performance details might carry composer-specific information that our models never saw.
  5. No hyperparameter optimization. We used reasonable default architectures but didn't systematically tune hyperparameters. The CNN in particular might benefit from deeper architectures or different filter configurations (Won et al., 2020).
  6. Single train/test split. We used one 80/20 split. Cross-validation would provide more reliable performance estimates and confidence intervals.
  7. No hybrid models. We compared pure LSTM and pure CNN architectures. Hybrid approaches like CRNNs, which combine convolutional feature extraction with recurrent sequence modeling, might outperform both (Choi et al., 2017). Transformer-based models have also shown promise for music tasks (Huang et al., 2019).
  8. Segment-level evaluation. We classified individual segments rather than full pieces. A voting or aggregation scheme across segments from the same piece might improve accuracy, especially for the CNN.
